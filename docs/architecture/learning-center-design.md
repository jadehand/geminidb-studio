# GeminiDB Studio 学习中心与分层引导设计

日期：2026-07-31
目标版本：v0.7.x
状态：已确认设计，待实施

## 1. 背景

现有首次引导包含 10 个步骤，覆盖连接、Database、目录、编辑器、Schema、查询结果、导出、时间转换和批量造数。随着 Measurement 数据编辑、离线知识库和本地 Claude 助手加入，继续向同一条 Tour 追加步骤会带来三个问题：

1. 首次体验过长，用户在真正执行第一次查询前需要连续阅读大量说明。
2. 尚未遇到具体场景时，用户难以记住高级功能。
3. 完成或跳过首次引导后，缺少集中、可重复进入的功能学习入口。

本设计不引入第三方引导框架，继续复用现有 `FeatureTour` 的高亮、定位、键盘与深色模式能力。

## 2. 目标

- 新用户在 5–6 步内完成第一次成功查询。
- 高级功能按主题提供 3–5 步短引导，可随时重复播放。
- 顶部问号成为统一学习入口，不再直接重播唯一的长 Tour。
- 用户第一次进入复杂功能时获得一次简短提示，之后不再打扰。
- 版本升级后只介绍新增能力，不重新播放首次引导。
- 所有状态仅保存在本地，不引入账号、遥测或云端进度。

## 3. 信息架构

### 3.1 第一层：首次快速上手

首次启动自动播放，目标是完成最短成功路径：

1. 新建 GeminiDB 连接。
2. 选择 Database。
3. 打开数据目录并选择 Measurement。
4. 在编辑器编写或补全 InfluxQL。
5. 安全执行查询。
6. 查看结果与时间显示。

首次引导不再介绍导出、时间转换、批量造数、知识库或 Claude 助手。

### 3.2 第二层：专题引导

学习中心提供以下专题：

| 专题 | 主要内容 | 预计步骤 |
|---|---|---:|
| 快速上手 | 首次查询主线 | 6 |
| 查询效率 | 补全、Schema、格式化、收藏、导出、时间转换 | 5 |
| 查看与编辑数据 | 查看数据、时间显示、搜索、开发/测试环境编辑 | 4 |
| 离线知识库 | 搜索概念与语法、插入示例到新查询 | 3 |
| 批量造数 | 环境限制、四步向导、预览和风险确认 | 4 |
| Claude 助手 | 普通聊天、显式上下文、查询诊断、本机历史 | 4 |

专题可重复播放。播放前由 App 将界面准备到正确工作区或工具窗口；Tour 本身只负责展示，不直接执行业务动作。

### 3.3 第三层：情境提示

以下功能第一次真正进入时显示一次非模态提示：

- 首次打开 Measurement 数据页：说明时间格式、搜索和编辑环境限制。
- 首次打开批量造数：说明必须先预览，生产环境不可用。
- 首次打开 Claude 助手：说明默认不附带 SQL、错误或 Schema，返回的 SQL 不会自动执行。
- 首次打开离线知识库：说明内容完全离线，语法示例只插入、不自动执行。

提示必须可立即关闭，并提供“查看专题引导”。同一提示关闭或完成后不再自动出现。

## 4. 顶部问号与学习中心

现有顶部问号按钮改为打开 `LearningCenter` 对话框。

对话框结构：

1. 标题区：`学习中心`、简短说明、关闭按钮。
2. “推荐开始”卡片：快速上手，展示完成状态和开始/重新体验按钮。
3. “实用功能”卡片列表：其余五个专题。
4. “本版本新功能”区域：本地 Claude 助手、Measurement 数据查看/编辑、离线知识库等。
5. 底部说明：学习进度仅保存在本机，可随时重置。

每张专题卡包含：

- 图标与标题；
- 1 句适用场景；
- 预计步骤数；
- 状态：未体验、已完成、已跳过；
- 主操作：开始体验或重新体验。

不使用百分比或积分，避免把工具学习游戏化。

## 5. 状态模型

替换单一 `gdb.onboarding.v3.status`，使用版本化本地状态：

```ts
type GuideStatus = 'new' | 'completed' | 'skipped'

type LearningProgressV1 = {
  version: 1
  topics: Record<GuideTopicId, GuideStatus>
  hints: Partial<Record<GuideHintId, 'dismissed' | 'completed'>>
  seenRelease: string
}
```

存储键：`gdb.learningCenter.v1`

迁移规则：

- 旧状态为 `completed`：快速上手记为已完成。
- 旧状态为 `skipped`：快速上手记为已跳过。
- 旧状态缺失或非法：快速上手为 `new`。
- 其他专题初始均为 `new`。
- 迁移成功后无需删除旧键，便于降级版本读取。

状态更新必须经过纯函数模块，视图不直接拼装或修改存储对象。

## 6. 模块与 interface

### `learning-center.ts`

深模块，负责：

- 专题、步骤和新功能元数据；
- 旧 onboarding 状态迁移；
- 状态规范化；
- 完成、跳过、关闭提示和版本已读操作；
- 选择首次应自动播放的引导。

对外 interface 只暴露元数据查询和状态转换，不访问 React。

### `LearningCenter.tsx`

只负责学习中心对话框展示和用户动作：

- 读取已经规范化的专题及进度；
- 触发开始专题、重置进度和关闭；
- 不负责切换工作区或写 localStorage。

### `FeatureTour.tsx`

保留现有定位与键盘逻辑，扩展：

- 接收专题标题；
- 步骤缺少目标时显示可理解的回退卡片，而不是整个 Tour 消失；
- 完成/跳过回调携带专题 ID；
- 允许从学习中心关闭后启动指定专题。

### `App.tsx`

只协调：

- 打开/关闭学习中心；
- 根据专题准备 `query` 工作区、侧边工具和必要页签；
- 持久化 `LearningProgressV1`；
- 决定是否显示一次性情境提示。

## 7. 界面准备规则

- 快速上手、查询效率：切到 `query` 工作区。
- 离线知识库：切到 `query`，打开左侧 `knowledge` 工具。
- Claude 助手：切到 `query` 工作区并高亮查询窗口内的助手入口。
- 查看与编辑数据：若已有 Measurement 数据页则聚焦；否则专题先解释从目录右键“查看数据”的入口。
- 批量造数：只高亮入口，不自动打开向导，避免在环境不满足时制造错误。

Tour 不自动连接数据库、不执行 SQL、不写入数据、不创建 Claude 助手会话。

## 8. 升级提示

当 `seenRelease !== '0.7'` 且用户不是全新安装时：

- 顶部问号显示一次轻量提示点；
- 学习中心顶部展示“v0.7 新功能”；
- 用户打开学习中心即记为已读；
- 不自动弹出模态框，不打断工作。

## 9. 可访问性与视觉

- 学习中心使用 `role="dialog"`、`aria-modal="true"`，打开后聚焦标题或关闭按钮。
- Escape 关闭学习中心；Tour 中 Escape 仍表示跳过当前专题。
- 专题卡使用真实按钮，不把整个卡片伪装成点击区域。
- 浅色、深色均复用现有设计变量；新 CSS 不写白色硬编码表面。
- 窄屏下卡片单列，学习中心高度不超过视口并内部滚动。
- 遵守 `prefers-reduced-motion`。

## 10. 测试

### 纯逻辑

- v3 状态正确迁移到 v1 学习进度。
- 非法、缺字段和未来版本状态安全回退。
- 完成、跳过、提示关闭和版本已读不改变无关字段。
- 首次自动播放只选择快速上手。

### Web 结构与交互

- 顶部问号打开学习中心，不直接启动 Tour。
- 六个专题均有标题、场景、步骤和状态。
- 启动专题时准备正确工作区/侧边工具。
- 完成或跳过后状态持久化。
- 情境提示只自动出现一次。
- Agent SQL 打开新查询页签的行为不受影响。

### 回归

- 现有 Web、Bridge、TypeScript 和生产构建全部通过。
- 手工检查浅色/深色、1366×768 和窄屏布局。

## 11. 非目标

- 不做云端学习进度、账号同步或团队管理。
- 不做遥测、功能使用统计或推荐算法。
- 不自动执行查询、写入、批量造数或 Agent 工具。
- 不在本阶段引入视频、外部文档站或第三方 Tour 依赖。
- 不把所有按钮都加 Tooltip；只覆盖高价值复杂流程。

## 12. 验收标准

1. 新用户首次引导不超过 6 步。
2. 顶部问号可打开学习中心并启动任一专题。
3. 六个专题均可重复播放并记录本地状态。
4. 四类情境提示最多自动出现一次。
5. 升级用户不会被重新强制播放首次引导。
6. 引导不会自动访问数据库或执行任何变更操作。
7. 深色、窄屏和键盘操作可用。
8. 全量自动化测试与生产构建通过。
