# Local Mock GeminiDB Design

## Context

GeminiDB Studio needs a repeatable local environment for exercising its database workflow, while contributors may not have access to a paid GeminiDB Influx instance. The production Bridge already talks to GeminiDB through the InfluxDB 1.x HTTP contract, so the development substitute should emulate that boundary instead of adding a special application mode.

## Decision

Add an independent Node.js development server at `scripts/mock-geminidb.mjs`. It listens on `127.0.0.1:8765`, keeps all data in memory, accepts the documented demo credentials, and is started only through `npm run dev:mock`. It is not referenced by Tauri, the production Bridge lifecycle, sidecar packaging, or release workflows.

The Mock will implement only the HTTP behavior exercised by the current Bridge:

- Basic Auth validation.
- `GET /query` with `SHOW DATABASES`, `SHOW MEASUREMENTS`, `SHOW FIELD KEYS`, `SHOW TAG KEYS`, `SHOW TAG VALUES`, `SHOW RETENTION POLICIES`, `INSERT`, and the bounded `SELECT` form generated by Studio.
- `POST /write` with Influx Line Protocol, supported precisions, and optional retention policy.
- In-memory schema inference, exact timestamp storage, deterministic ordering, filtering by time bounds, and `LIMIT`/`OFFSET`.
- Seed data that lets a new connection immediately browse a database, inspect Schema, and query a day-table Measurement.
- Influx-style JSON error responses for malformed or unsupported requests.

## Data model

The server stores databases, Measurements, and points in Maps. A point contains an exact nanosecond timestamp string, tag values, and typed Field values. Writes with the same Measurement, timestamp, and complete tag set merge Field values, matching the overwrite behavior needed by Studio's online editing workflow.

Line Protocol parsing is deliberately bounded to the syntax Studio emits: escaped identifiers, quoted strings, booleans, signed integers with the `i` suffix, finite floats, and an optional timestamp. Multi-line `/write` batches are accepted atomically after every line validates. `INSERT` accepts the same Line Protocol payload after its command prefix.

## Query behavior

`SELECT` supports `SELECT * FROM <measurement>`, optional nanosecond time bounds joined with `AND`, `ORDER BY time ASC|DESC`, and `LIMIT`/`OFFSET`. It returns InfluxDB 1.x `results[].series[]` JSON and honors the requested `epoch` (`ns` or `ms`). Unsupported projections, expressions, grouping, aggregation, regex Measurements, or general predicates return a clear Mock limitation error rather than pretending to be compatible.

## Safety and lifecycle

- Bind only to loopback.
- Never read production credentials or make outbound requests.
- Store no data on disk; process exit clears everything.
- Use fixed demo credentials only for local development.
- Keep the Mock out of desktop startup, sidecar builds, and release assets.

## Verification

Automated tests cover authentication, catalog and Schema queries, seed queries, Line Protocol and `INSERT` writes, overwrite editing, time filtering, pagination, validation, and lifecycle. An end-to-end browser check connects Studio to the Mock and verifies the path `connection -> catalog -> query -> write -> query` without a real GeminiDB instance.
