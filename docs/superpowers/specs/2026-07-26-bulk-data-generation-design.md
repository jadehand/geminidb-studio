# GeminiDB Studio v0.5.0 批量造数设计规格

## 1. 文档状态

- 目标版本：`0.5.0`
- 基线版本：`0.4.10`
- 日期：`2026-07-26`
- 状态：待用户书面审阅
- 目标用户：需要为 GeminiDB Influx 测试环境补造时序数据的开发与测试人员

## 2. 目标与成功标准

v0.5.0 只新增一项完整能力：用户针对当前测试连接、当前 Database 和一个已有逻辑表前缀，选择最多 7 个日期，配置 Tag、Field 与字段约束，预览确定性的样本和写入风险，再由 Bridge 以受控速率批量写入 GeminiDB Influx。

成功标准：

1. 用户可以从主界面顶部进入四步向导并完成一次造数任务。
2. 目标日期对应的天表不存在时标记为“待创建”，首次写入自动创建 measurement。
3. RP、Schema、点数、时间线和约束在 Bridge 侧得到权威校验。
4. 任务支持进度、取消、失败暂停、原批次重试和应用关闭保护。
5. 造数不能用于 `prod`、`dev`、未指定环境或只读连接。
6. 查询、Schema、历史、收藏、诊断和现有手工 `WRITE` 行为不发生回归。

## 3. 已选方案与备选方案

### 3.1 采用：Bridge 进程内任务管理器

前端只提交声明式配置；Bridge 负责预览、生成、Line Protocol 编码、批次调度、限流、重试、取消和状态查询。前端每 1 秒轮询任务状态。

优点：

- Web 与桌面端使用同一执行路径。
- 浏览器不需要持有 10 万点完整数据。
- 凭证和实际写入始终留在 Bridge。
- 与现有 Node Bridge 架构一致，不引入额外服务。

限制：

- 任务状态只存在于当前 Bridge 进程。
- 应用关闭后任务终止，不能跨重启续传。

### 3.2 不采用：前端生成完整 Line Protocol

该方案实现快，但会放大浏览器内存占用，也会造成预览与执行逻辑重复，并让取消、重试和凭证边界变差。

### 3.3 不采用：独立持久化 Worker 或队列

该方案可以跨重启恢复，但需要任务数据库、凭证恢复、后台生命周期和迁移机制，超过 v0.5.0 的单机 MVP 范围。

## 4. 核心领域规则

### 4.1 连接与目标范围

- 整个 GeminiDB Studio 同一时间最多运行一个造数任务。
- 仅 `environment === "test"`、非只读、已连接且已选择 Database 的连接可进入向导。
- 前端禁用入口只是用户提示；Bridge 必须再次检查测试环境和只读状态。
- 现有连接已经支持 `prod/test/dev`。缺失 `environment` 的旧连接按 `dev` 处理，不执行自动猜测或自动迁移。
- 一个任务只处理当前 Database 下的一个逻辑表前缀。
- 用户必须从已有天表推导出的逻辑前缀中选择，不能任意输入全新前缀。

### 4.2 天表模型

- 物理 measurement 命名为 `<prefix>_<unixSeconds>`。
- 后缀是目标日期在 `Asia/Shanghai` 当日 `00:00:00` 的 Unix 秒。
- 日期和每日起止时间固定按北京时间解释，写入时转换为 UTC 毫秒时间戳。
- 目标天表存在时显示“已存在”；不存在时显示“待创建”。
- “待创建”不调用单独建表接口。Influx 首次写入该 measurement 时完成创建。
- 多日期任务按日期从早到晚逐张天表执行；一张完成后才进入下一张。

### 4.3 Schema 来源

- 默认使用该逻辑前缀下最新一张已有天表作为 Schema 来源。
- 用户可以切换到同前缀的其他已有天表。
- Bridge 每次预览和正式执行前重新读取 Schema。
- 预览时比较 Schema 来源与本任务中已经存在的目标天表，不扫描无关历史天表。
- 如果目标天表缺少或多出 Tag/Field，界面提示差异，但仍只按来源 Schema 生成，不做并集或交集。
- 如果同名 Field 在来源表和目标表中的类型不同，阻止执行，避免部分批次因类型冲突失败。
- 来源 Schema 无法识别的 Field 类型会阻止预览。

### 4.4 RP 规则

- 用户只能选择 Database 中真实存在的 Retention Policy。
- RP 不存在时阻止预览和执行。
- RP duration 为 `0` 时按无限保留处理。
- 对有限 duration，任何目标时间点早于 `当前 Bridge 时间 - duration` 时阻止执行，不允许强确认绕过。
- `influxWrite` 必须通过 `/write?db=...&rp=...&precision=ms` 显式传递 RP。

### 4.5 日期与采样

- 日期模式只有“最近 N 天”和“指定日期”。
- “指定日期”在一个日历控件中支持单选或多选，不再拆成“指定一天/指定多天”。
- 单任务最多选择 7 个日期，可以不连续。
- “最近 N 天”要求 `1 <= N <= 7`，包含今天。
- 允许未来日期，但预览必须显示高风险警告并要求额外勾选确认。
- 每个日期配置相同的每日开始时间、结束时间和采样间隔。
- 每日开始时间必须早于或等于结束时间；v0.5.0 不允许一个日期配置跨越次日。
- 时间槽为闭区间：从开始时间起，每次增加采样间隔，直到 `timestamp <= 结束时间`。
- 预设间隔：1 秒、5 秒、10 秒、30 秒、1 分钟、5 分钟、15 分钟、30 分钟、1 小时。
- 自定义间隔必须是整数秒，范围为 1 秒到 24 小时；不支持毫秒级采样。

### 4.6 Tag 生成

每个 Schema Tag 必须配置且至少产生一个值。支持：

1. 手工候选列表；一个候选值等价于固定值。
2. 序列生成：前缀、起始整数、数量、补零宽度，例如 `node-001`。数量必须是 1 到 1000 的整数。
3. 从 Schema 来源天表读取已有 Tag 值。

读取已有值时最多返回 1000 个去重值。超过上限时返回 `truncated: true`，界面提示用户缩小候选集合，不静默把截断结果当作全集。

每个时间槽会为所有 Tag 候选值的笛卡尔积生成一个点。组合顺序固定为 Schema Tag 顺序，候选值保持配置顺序，以保证重试时顺序稳定。

Tag 值去除首尾空白后不得为空。数值生成器拒绝 `NaN`、无穷值和不符合 integer 类型的非整数参数；布尔随机概率必须在 0 到 100 之间。

### 4.7 Field 生成

支持四类 Influx Field：

- `float`：固定值、均匀随机区间、递增。
- `integer`：固定值、均匀随机区间、递增，写入值带 `i` 后缀。
- `string`：固定值、候选值列表。
- `boolean`：固定值、按百分比概率随机。

递增顺序固定为：日期升序、时间升序、Tag 组合顺序。字符串、measurement、Tag key/value 和 Field key/value 必须按 Line Protocol 规则转义。

### 4.8 Field 约束

- 所有约束按 AND 组合。
- 左值必须是 Field；右值可以是同类型 Field 或固定值。
- 数值类型支持 `>`、`>=`、`<`、`<=`、`=`、`!=`。
- 字符串和布尔类型只支持 `=`、`!=`。
- v0.5.0 不支持 Tag 条件、OR、嵌套组、脚本、函数或跨 measurement 约束。

Bridge 将 Field 间约束构建为有向依赖图，右侧 Field 先于左侧 Field 生成。以下情况阻止预览：

- 类型不匹配。
- 自引用或依赖环。
- 数值区间交集为空。
- 固定值与生成范围冲突。
- 字符串或布尔候选集合无法满足相等/不等条件。

生成时先按拓扑顺序生成无依赖 Field，再将约束转换成依赖 Field 的有效区间或候选集合，从可行域中取值。执行阶段不采用“生成后丢弃不合格点”的方式，因此计划点数与实际目标点数一致。

### 4.9 上限计算

- `tagCombinationCount = 各 Tag 候选值数量的乘积`。
- `pointCount = 所有目标日期时间槽数量之和 × tagCombinationCount`。
- `maxNewSeries = 目标日期数 × tagCombinationCount`，表示最坏情况下最多新增的时间线，不声称是精确新增值。
- `pointCount > 100000` 时阻止预览。
- `maxNewSeries > 10000` 时阻止预览。
- 上限必须使用安全整数计算，并在乘法中提前检测溢出。

## 5. 用户体验

### 5.1 入口

- 入口位于顶部左侧、Database 选择器之后。
- 与 Database 选择器保留约 24px 的分组间距，不紧贴。
- 使用“图标 + 批量造数”的普通描边按钮，不使用危险色或主按钮样式。
- 任务运行时按钮显示 `批量造数 42%`；点击回到当前任务进度。
- 禁用时保留入口，并通过 `title` 和可见提示说明原因。

### 5.2 四步向导

向导为居中的大尺寸模态框，视觉与现有 GeminiDB Studio 的颜色、边框、字号、深浅主题和按钮风格一致。

1. **目标与 RP**
   - 显示当前测试连接和当前 Database。
   - 选择一个已有逻辑表前缀。
   - 选择 Schema 来源天表。
   - 选择 RP，并显示 duration。
2. **时间与天表**
   - 最近 N 天或指定日期。
   - 最多 7 天。
   - 每日起止时间与采样间隔。
   - 展示目标 measurement、日期、已存在/待创建状态、每天点数。
3. **字段与约束**
   - Tag 和 Field 在同一步配置。
   - 参数输入随生成方式变化，不显示无意义的候选框或横线占位。
   - 比较操作符使用居中的自绘符号菜单：`>`、`≥`、`<`、`≤`、`=`、`≠`。
   - 所有控件使用清晰的中文字体和不小于现有表单的字号。
4. **预览与执行**
   - 显示目标、RP、日期、天表状态、点数、最多新增时间线、Tag/Field/约束摘要。
   - 默认显示 20 条确定性表格样本。
   - 可切换查看这 20 条对应的 Line Protocol。
   - 显示阻断项、一般提醒和高风险警告。

### 5.3 确认规则

- 正式执行始终要求用户输入逻辑表前缀。
- 任一目标天表已存在时，明确提示 Influx upsert 语义：同 measurement、Tag 集和时间戳下，同名 Field 会被覆盖，其他 Field 保留。
- 包含未来日期时，增加“我确认包含未来时间点”勾选项。
- “待创建”天表在确认区列出，不额外要求单独建表。
- RP 不存在、超出保留期、约束不可满足、点数超限或时间线超限属于阻断项，不能通过确认绕过。

### 5.4 任务进度与最小化

- 任务状态包括：`queued`、`running`、`retrying`、`paused`、`cancelling`、`cancelled`、`succeeded`、`failed`。
- 进度显示当前天表、完成批次数、成功点数、总点数、百分比、重试次数和最近错误。
- 用户可以最小化进度弹窗并继续查询。
- 完成、暂停、失败或取消时显示应用内通知。
- 任务运行期间再次点击入口，不创建新任务，直接打开当前进度。

### 5.5 停止与关闭应用

- 用户点击“停止任务”后显示二次确认。
- 确认停止后，Bridge 不再调度新批次；等待已在途请求完成，然后进入 `cancelled`。
- 已成功写入的数据保留，不尝试回滚或删除。
- 桌面端收到关闭窗口请求且任务未结束时，阻止关闭并显示：
  - 当前成功点数和总点数。
  - “关闭会停止任务，已写入数据不会撤销”。
  - `继续造数`。
  - `停止任务并退出`。
- 选择退出后先请求取消，等待任务终止；超过 3 秒仍未终止则允许关闭，Bridge 退出流程负责停止后续批次。
- Web 模式使用浏览器原生 `beforeunload` 提醒，因为浏览器不允许自定义关闭文案。
- 应用关闭后任务不继续，也不支持重新打开后续传。

### 5.6 草稿与历史

- 草稿存储键：`gdb.bulkData.draft.v1`。
- 配置变化后防抖保存一份草稿；不保存密码、会话、预览样本、Line Protocol 或任务随机种子。
- 再次进入时提供“继续编辑”和“放弃草稿”，继续前重新校验远端 Schema、RP 和天表状态。
- 历史存储键：`gdb.bulkData.history.v1`，只保留最近 20 条摘要。
- 历史包含目标、日期、计划/成功点数、状态、开始时间、耗时和错误摘要。
- 历史不保存完整生成数据、凭证、随机种子或可跨重启断点。
- 向导左侧底部提供“最近任务”。
- 历史支持“复制为新任务”，但会创建新随机种子并强制重新预览、确认。

## 6. API 与数据流

### 6.1 辅助接口

```text
GET /retention-policies?database=<db>
GET /tag-values?database=<db>&measurement=<source>&tag=<tag>&limit=1000
```

`GET /retention-policies` 返回：

```json
{
  "items": [
    {
      "name": "autogen",
      "durationMs": 604800000,
      "isDefault": true
    }
  ]
}
```

`GET /tag-values` 返回：

```json
{
  "values": ["node-01", "node-02"],
  "truncated": false
}
```

### 6.2 预览

```text
POST /bulk-jobs/preview
```

请求只包含声明式配置：Database、逻辑前缀、Schema 来源、RP、日期与时间、Tag 生成器、Field 生成器和约束。

Bridge 执行：

1. 校验连接为测试环境且可写。
2. 重新读取 RP、measurement 列表和来源 Schema。
3. 归一化日期与生成配置。
4. 校验约束、点数和时间线上限。
5. 创建随机种子和 15 分钟有效的 `previewId`。
6. 生成 20 条确定性样本和 Line Protocol。
7. 返回计划摘要、阻断项、警告、确认要求和 `previewId`。

有阻断项时返回结构化的 `422 BULK_PLAN_INVALID`，不创建可执行预览。

### 6.3 创建任务

```text
POST /bulk-jobs
```

请求：

```json
{
  "previewId": "opaque-id",
  "confirmation": {
    "typedPrefix": "cpu",
    "futureDatesAccepted": true,
    "overwriteAccepted": true
  }
}
```

Bridge 在创建任务前重新检查环境、只读状态、RP、Schema 和目标天表状态。与预览不一致时返回 `409 STALE_BULK_PREVIEW`，要求用户重新预览。

同一时间已有未结束任务时返回 `409 BULK_JOB_ACTIVE`，并附带当前任务 ID。

### 6.4 状态、继续和取消

```text
GET  /bulk-jobs/active
GET  /bulk-jobs/:id
POST /bulk-jobs/:id/resume
POST /bulk-jobs/:id/cancel
```

- `active` 用于应用重渲染或用户最小化后重新找到当前任务。
- `resume` 只允许对 `paused` 任务调用，继续使用相同种子和相同批次内容。
- `cancel` 幂等；对终态任务调用时返回当前终态。
- 活跃任务绑定到规范化 endpoint 与 username 组成的连接身份。重新登录同一连接后可以重新查看和取消任务；其他连接只能收到“已有任务运行”的摘要，不能读取样本或执行控制操作。

### 6.5 任务调度

- 每批最多 1000 点。
- 单张天表内部最多 2 个在途写请求。
- 不向用户暴露批大小、并发数或速率参数。
- HTTP/HTTPS Agent 开启 Keep-Alive，每个目标最多 2 个 socket。
- 对超时、连接重置、HTTP 429、500、502、503、504执行最多 3 次重试。
- 退避间隔为 250ms、500ms、1000ms，并加入不超过 20% 的抖动。
- 其他 4xx 不重试。
- 一个批次重试三次仍失败时停止调度新批次，等待在途批次结束，任务进入 `paused`。
- 明确不可恢复的认证、环境、RP 或 Schema 错误直接进入 `failed`，不能对该任务调用 `resume`。
- 因并发 2 可能存在后续批次先完成，任务保存已完成批次集合；继续时重试失败批次并跳过已完成批次。
- 随机种子、日期/时间/Tag 顺序和批次边界固定，所以同一批次的重试内容逐字节一致。

## 7. Influx 写入语义

- 精度固定为 `ms`，避免 JavaScript 表示纳秒整数时丢失精度。
- 每行 Line Protocol 包含 measurement、完整 Tag 集、完整 Field 集和 UTC 毫秒时间戳。
- 相同 measurement、Tag 集和时间戳按 Influx upsert 处理。
- 系统不预查询每个时间点，也不声称能精确统计覆盖数量。
- 结果报告使用“存在覆盖可能”，只有 GeminiDB 返回可验证数据时才展示精确覆盖数。
- 不提供删除、回滚或“撤销本次造数”。

## 8. 模块边界

### 8.1 Web

- `BulkDataWizard.tsx`：四步向导、历史视图、进度视图和确认交互。
- `bulk-data.ts`：纯类型、草稿/历史归一化、前端即时估算与展示辅助函数。
- `bulk-data.css`：批量造数独立样式和响应式规则。
- `api.ts`：新增辅助、预览、创建、状态、继续和取消 API。
- `App.tsx`：只负责顶部入口、当前连接/Database 上下文、全局单任务状态、通知和关闭保护；不内联生成器或向导细节。
- `desktop.ts` 或新建 `app-close.ts`：封装 Tauri 窗口关闭拦截，Web 使用 `beforeunload` 回退。

### 8.2 Bridge

- `bulk-plan.mjs`：请求归一化、北京时间日期计算、天表命名、RP/Schema 校验、上限计算和预览模型。
- `bulk-generator.mjs`：确定性 PRNG、Tag/Field 生成、约束依赖图、可行域求值和 Line Protocol 编码。
- `bulk-jobs.mjs`：全局单任务状态机、批次调度、重试、暂停、继续、取消和关闭。
- `influx-client.mjs`：Keep-Alive、RP 查询、Tag 值查询和带 RP 的批量写入。
- `server.mjs`：路由、认证、请求体边界和错误映射；不承载生成算法。

## 9. 错误处理

错误响应保持现有 `{code, message, requestId}` 形状，并增加可选 `details`。

主要错误码：

- `BULK_TEST_ENV_REQUIRED`
- `READ_ONLY_CONNECTION`
- `BULK_JOB_ACTIVE`
- `BULK_PLAN_INVALID`
- `STALE_BULK_PREVIEW`
- `RP_NOT_FOUND`
- `RP_RETENTION_EXCEEDED`
- `SCHEMA_SOURCE_NOT_FOUND`
- `SCHEMA_CHANGED`
- `TAG_VALUE_LIMIT`
- `POINT_LIMIT_EXCEEDED`
- `SERIES_LIMIT_EXCEEDED`
- `CONSTRAINT_UNSATISFIABLE`
- `BULK_JOB_NOT_FOUND`
- `BULK_JOB_NOT_PAUSED`

前端按 `code` 映射到对应步骤和控件，不依赖中文错误文案做逻辑判断。

## 10. 安全与资源控制

- Bridge 继续只监听 `127.0.0.1` 并执行 Origin 白名单校验。
- 所有造数接口都要求有效 Bearer 会话。
- 登录时把连接环境写入 Bridge 会话；Bridge 不接受每次造数请求临时声明环境。
- JSON 请求体上限为 1 MiB，声明式配置不得包含完整点集或任意脚本。
- 日志和历史不记录密码、Authorization、完整 Line Protocol 或直接个人联系/支付信息。
- 每个批次最多在内存中保留 1000 行，不预先构造完整任务数据。
- 任务结束、会话失效或 Bridge 关闭时释放定时器、AbortController 和 Keep-Alive socket。

## 12. 可观测性

- Bridge 为每个任务生成 `jobId`，每个请求保留现有 `requestId`。
- Bridge 日志只记录任务状态转换、批次号、点数、耗时、重试次数和脱敏错误。
- 前端最终报告展示成功点数、未写点数、完成天表、当前/失败天表、耗时和错误摘要。
- 不展示无法可靠获得的“精确覆盖点数”。

## 13. 版本与兼容

以下版本统一升级到 `0.5.0`：

- 根 `package.json`
- `src-tauri/Cargo.toml`
- `src-tauri/tauri.conf.json`
- Bridge `/health`
- `CHANGELOG.md`

新增接口和模块不改变现有 `/query`、`/tables`、`/schema`、`WRITE` 路径。批量造数入口可独立隐藏作为紧急回退，但 Bridge 仍必须保持旧功能兼容。

## 14. 非目标

v0.5.0 不包含：

- 生产、开发或未指定环境造数。
- 多逻辑前缀、多 Database 或多连接并行任务。
- 跨重启恢复和后台常驻写入。
- 外部 CSV/JSON 导入。
- 任意脚本、表达式语言、OR/嵌套条件组或 Tag 条件。
- 正态分布、趋势函数、周期函数或模板市场。
- 精确覆盖检测、自动删除、回滚或撤销。
- 毫秒级采样。
- 用户可调并发、批大小或随机种子。
