# GeminiDB Studio 轻量 Claude 助手设计

日期：2026-08-19

状态：已确认方向，待实施

## 1. 背景与目标

GeminiDB Studio v0.7.1 的 Agent 工作台包含独立一级工作区、会话与 Run 模型、SSE 事件流、工具编排、数据库权限策略、Anthropic API 回退和本地持久化。这套能力超过当前产品的核心需求，也增加了配置、安全审计和维护成本。

本次改造将其收敛为类似 Obsidian Claude 插件的本地助手：依赖本机 Claude CLI，支持普通上下文聊天和 SQL 诊断，并在本机持久保存可查看的聊天历史。助手只生成文本和查询建议，不执行数据库操作。

## 2. 产品边界

### 2.1 保留能力

- 检测本机 Claude CLI 是否安装并可用。
- 普通多轮聊天。
- 一键诊断当前 InfluxQL、查询错误和相关 Schema。
- 用户主动选择附加当前 SQL、错误或 Schema 作为聊天上下文。
- 新建、查看、搜索、切换和删除本地聊天历史。
- 将 Claude 返回的 InfluxQL 复制或打开到新的查询页签，但绝不自动执行。

### 2.2 删除能力

- Agent 一级工作区及其导航入口。
- `/agent/*` 会话、Run、SSE 和 Provider API。
- Agent 工具调用、数据库查询、写入和批量造数能力。
- Agent 环境权限策略、工具预算和执行轨迹。
- Anthropic API Key 与 API Provider 回退。
- Agent 专用会话、Run、事件和工具结果存储。

上述内容不仅从界面和路由中移除，对应的前端组件、样式、Bridge 模块、类型、客户端、测试和无用文档引用也要物理删除。仅当一段代码被新的 Claude CLI 聊天或诊断直接复用时才保留，并应改为 Claude 助手领域命名，避免残留 Agent 概念和死代码。

### 2.3 安全边界

- Claude 助手只能调用本机 `claude` 命令。
- Bridge 不向 Claude 提供 Shell、文件系统或数据库工具。
- 数据库密码、认证 Token、完整连接地址和 API Key 不进入提示词或历史记录。
- 助手返回的 SQL 必须由用户复制或打开到查询页签后手动执行。
- 上下文默认不附带数据库内容，只有普通聊天中的显式勾选或“诊断当前查询”动作才附带。

## 3. 用户体验

查询工作区增加“Claude 助手”入口，打开右侧抽屉。抽屉由历史区和对话区组成：宽屏并排显示，窄屏通过返回按钮切换。关闭抽屉不丢失当前会话。

普通聊天输入框上方提供上下文开关：当前 SQL、最近一次错误、当前 Measurement Schema。每次发送时把选中的上下文作为该条消息的只读附件快照，并在消息旁显示附件标签。

“诊断当前查询”从查询错误区域或助手空状态进入，自动创建或复用当前会话，并附带当前 SQL、错误和可用 Schema。回复应优先给出原因、修正后的 InfluxQL 和注意事项。

历史列表支持新建、标题搜索、切换和删除。首条用户消息生成本地标题，用户可重命名。删除需要应用内确认，取消为默认动作并支持 Esc。

## 4. 架构

### 4.1 Web 前端

新增轻量的 Claude 助手组件和客户端模型，职责包括：

- 管理抽屉、历史列表、当前会话和发送状态。
- 构造显式选择的上下文快照。
- 展示 Markdown 文本与 InfluxQL 代码块。
- 从代码块提供“复制”和“打开到新查询”操作。
- 在 CLI 不可用、超时或失败时展示可恢复错误。

`App.tsx` 只负责提供当前查询、错误、Schema 和新建查询页签回调；聊天状态不进入全局查询工作区快照。

### 4.2 Bridge API

保留 `/claude/probe`，新增或收敛以下接口：

- `GET /claude/sessions`：读取会话摘要。
- `POST /claude/sessions`：创建会话。
- `GET /claude/sessions/:id`：读取完整消息。
- `PATCH /claude/sessions/:id`：重命名会话。
- `DELETE /claude/sessions/:id`：删除会话。
- `POST /claude/sessions/:id/messages`：保存用户消息、调用 CLI、保存助手回复并返回结果。
- `POST /claude/diagnose`：兼容现有诊断入口，内部复用同一 CLI 调用与消息格式化能力。

普通聊天使用请求/响应，不引入 SSE。单次 CLI 调用设置超时和输出大小限制，同一会话只允许一个在途请求。

### 4.3 Claude CLI 调用

CLI 适配器统一负责版本探测、登录状态探测、进程超时、输出限制和错误映射。普通聊天把历史消息、当前用户问题和已选择的上下文组装成结构化提示词；诊断使用固定系统指令约束输出为原因、修复建议和 InfluxQL。

旧的 API Provider 和工具调用协议不会进入新适配器。CLI 返回文本经过长度校验和敏感字段清理后再持久化。

### 4.4 本地存储

存储位于桌面应用数据目录的 `claude-assistant` 子目录；直接运行 Bridge 时使用既有开发数据目录。采用一个索引文件和每会话一个 JSON 文件，避免所有历史集中在单个大文件。

会话保存：ID、标题、创建/更新时间、消息。消息保存：角色、纯文本内容、时间、上下文附件摘要。附件只保存 SQL、错误文本和 Schema 字段/标签，不保存连接凭据。

写入采用临时文件加原子替换；启动时隔离损坏文件，不能因一条损坏会话阻断其他历史。历史总量设置合理上限，并对单条消息、上下文和 CLI 输出分别限长。

## 5. 迁移与兼容

现有 Agent 历史不自动迁移，因为其中包含 Run、工具轨迹和不同的数据模型。升级后旧数据留在原应用数据目录，不再读取，也不会自动删除，避免不可恢复的数据损失。

现有 Claude 诊断入口保持可用，但底层改为复用新的 CLI 适配器。旧的前端 Agent 工作区状态在读取工作区快照时被忽略，并回退到查询工作区。

README、架构文档、学习中心和功能引导同步移除 Agent 工具执行与 API Provider 描述，改为本地 Claude 助手说明。

## 6. 错误处理

- CLI 未安装：提示安装 Claude Code，并显示检测命令。
- CLI 未登录：提示执行本机登录，不提供 API Key 回退。
- CLI 超时：保留用户消息，允许重试，不保存空助手消息。
- 用户取消：终止当前 CLI 子进程，保留已发送消息。
- 历史文件损坏：隔离损坏文件并继续加载其他会话。
- 上下文过大：前端预估、Bridge 最终裁剪，并明确提示被裁剪部分。

## 7. 测试与验收

- 前端：助手入口、历史操作、上下文显式选择、诊断入口、SQL 打开新页签、错误与取消状态。
- Bridge：CLI 探测、聊天提示词、超时/取消/输出限制、会话 CRUD、原子存储、损坏隔离、敏感字段过滤。
- 删除验证：不存在 Agent 一级入口、`/agent/*` 路由、SSE、数据库工具与 Anthropic API 配置。
- 回归：查询、Measurement 数据、写入、批量造数、笔记、学习中心和桌面关闭保护保持通过。
- 完整验证：`npm run check`、`npm run build`、`npm run test:web`、`npm run test:bridge`。

## 8. 非目标

- 不实现流式输出、多模型切换、联网搜索、文件附件、数据库自动操作和工作区级知识库。
- 不迁移或删除旧 Agent 历史。
- 不允许 Claude 自动执行生成的 SQL。
